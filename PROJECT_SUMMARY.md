# Construction Work Journal - Итоговый проект

## 📋 Обзор проекта

Полнофункциональное веб-приложение для учета выполненных работ на строительных объектах. Проект реализует все обязательные и дополнительные требования тестового задания.

## 🎯 Выполненные требования

### Обязательные требования ✅
- [x] **Список записей журнала** - таблица с датой, видом работ, объемом и исполнителем
- [x] **Сортировка и фильтрация** по дате с возможностью поиска
- [x] **Добавление записи** - форма с валидацией обязательных полей
- [x] **Удаление записи** - с подтверждением
- [x] **Сохранение в БД** - PostgreSQL с Prisma ORM
- [x] **React + TypeScript** - современный фронтенд
- [x] **API взаимодействие** - REST API между фронтендом и бэкендом

### Дополнительные требования ✅

- [x] **Справочник видов работ** - выбор из предзаполненного списка
- [x] **Пагинация** - навигация по страницам
- [x] **Поиск** - по дате и ФИО исполнителя

## 🏗️ Архитектура

### Backend (Node.js + Express + TypeScript)
- **Express** - веб-сервер
- **Prisma ORM** - работа с PostgreSQL
- **Zod** - валидация данных
- **Jest** - тестирование
- **Docker** - контейнеризация

### Frontend (React + TypeScript)
- **Vite** - сборщик
- **Material-UI** - компоненты интерфейса
- **React Query** - управление состоянием данных
- **React Hook Form + Yup** - формы и валидация
- **Date-fns** - работа с датами

### База данных (PostgreSQL)
- **Работа с датами** - оптимизированные индексы
- **Связи** - внешние ключи между таблицами
- **Триггеры** - автоматическое обновление временных меток

## 🚀 Функциональность

### Основные функции
1. **Просмотр журнала** - таблица с пагинацией и фильтрацией
2. **Добавление работ** - форма с выбором из справочника
3. **Редактирование** - изменение существующих записей
4. **Удаление** - с подтверждением действия
5. **Поиск** - по дате и исполнителю
6. **Справочник** - управление видами работ

### Технические особенности
- **Валидация** на двух уровнях (клиент/сервер)
- **Обработка ошибок** - информативные сообщения
- **Логирование** - мониторинг работы приложения
- **Тестирование** - unit и интеграционные тесты
- **Документация** - полная документация API

## 📊 Структура базы данных

### Таблицы
1. **work_types** - справочник видов работ
   - id (UUID)
   - name (string)
   - description (text)
   - unit (string)

2. **work_logs** - журнал работ
   - id (UUID)
   - work_date (date)
   - work_type_id (foreign key)
   - quantity (decimal)
   - worker_name (string)
   - notes (text)

## 🔧 Запуск проекта

### Вариант 1: Docker Compose (рекомендуется)
```bash
docker-compose up --build
```

### Вариант 2: Локальная разработка
```bash
# Backend
cd backend
npm install
npm run dev

# Frontend
cd frontend
npm install
npm run dev
```

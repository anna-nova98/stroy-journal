# 🏗️ Журнал работ на строительном объекте

Полнофункциональное веб-приложение для учета выполненных работ на строительных объектах. Проект реализует все требования тестового задания с дополнительными улучшениями.

## 🎯 Выполненные требования

### ✅ Обязательные требования
- **Список записей журнала** - таблица с датой, видом работ, объемом и исполнителем
- **Сортировка и фильтрация** по дате с возможностью поиска
- **Добавление записи** - форма с валидацией обязательных полей
- **Удаление записи** - с подтверждением
- **Сохранение в БД** - PostgreSQL с Prisma ORM
- **React + TypeScript** - современный фронтенд
- **API взаимодействие** - REST API между фронтендом и бэкендом

### ✅ Дополнительные требования
- **Редактирование записей** - полный CRUD функционал
- **Справочник видов работ** - выбор из предзаполненного списка
- **Пагинация** - навигация по страницам
- **Поиск** - по дате и ФИО исполнителя
- **Валидация** - на фронтенде и бэкенде
- **Адаптивный дизайн** - работает на мобильных устройствах

## 🏗️ Стек технологий

### Backend
- **Node.js** + **Express** + **TypeScript** - серверная платформа
- **PostgreSQL** - реляционная база данных
- **Prisma ORM** - современный ORM для работы с БД
- **Zod** - валидация схем данных
- **Jest** + **Supertest** - тестирование

### Frontend
- **React** + **TypeScript** - клиентская часть
- **Vite** - быстрый сборщик
- **Material-UI (MUI)** - компоненты для интерфейса
- **React Query** - управление состоянием данных
- **React Hook Form** + **Yup** - формы и валидация
- **Date-fns** - работа с датами

### Инфраструктура
- **Docker** + **Docker Compose** - контейнеризация
- **Nginx** - обратный прокси и балансировка нагрузки

## 📡 API Endpoints

Все API endpoints доступны по базовому URL: `http://localhost:5001/api`

### Журнал работ (`/api/work-logs`)

#### Получить список записей с пагинацией и фильтрацией
```http
GET /api/work-logs
```

**Параметры запроса:**
- `page` (опционально): Номер страницы (по умолчанию: 1)
- `limit` (опционально): Количество записей на странице (по умолчанию: 10)
- `sortBy` (опционально): Поле для сортировки (`workDate`, `quantity`, `workerName`, `workType.name`)
- `sortOrder` (опционально): Порядок сортировки (`asc` или `desc`)
- `startDate` (опционально): Начальная дата фильтрации (формат: YYYY-MM-DD)
- `endDate` (опционально): Конечная дата фильтрации (формат: YYYY-MM-DD)
- `workerName` (опционально): Фильтр по ФИО исполнителя
- `workTypeId` (опционально): Фильтр по ID вида работ
- `minQuantity` (опционально): Минимальный объем работ
- `maxQuantity` (опционально): Максимальный объем работ

**Примеры:**
```bash
# Получить первую страницу
curl "http://localhost:5001/api/work-logs"

# Фильтрация по дате
curl "http://localhost:5001/api/work-logs?startDate=2024-01-01&endDate=2024-01-31"

# Поиск по исполнителю
curl "http://localhost:5001/api/work-logs?workerName=Иванов"

# Сортировка по дате
curl "http://localhost:5001/api/work-logs?sortBy=workDate&sortOrder=desc"
```

#### Получить запись по ID
```http
GET /api/work-logs/:id
```

#### Создать запись
```http
POST /api/work-logs
Content-Type: application/json

{
  "workDate": "2024-01-15",
  "workTypeId": "uuid-вида-работ",
  "quantity": 100.5,
  "workerName": "Иванов Иван Иванович",
  "notes": "Примечания к работе"
}
```

#### Обновить запись
```http
PUT /api/work-logs/:id
Content-Type: application/json

{
  "workDate": "2024-01-16",
  "quantity": 150.0,
  "workerName": "Петров Петр Петрович"
}
```

#### Удалить запись
```http
DELETE /api/work-logs/:id
```
